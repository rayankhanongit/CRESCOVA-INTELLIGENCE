# Deployment notes

The goal so far has been a working local application. **Nothing here has been deployed, load-tested, or run on PostgreSQL.** Treat this as a checklist, not a tested procedure. Do not deploy without reviewing it against your own environment.

## Before exposing it beyond localhost

1. Set in `backend/.env`: `ENVIRONMENT=production`, a long random `SECRET_KEY` (`python -c "import secrets;print(secrets.token_urlsafe(48))"`), `CORS_ORIGINS` to your real origin, and `ALLOW_REGISTRATION=false` once accounts exist. Production forces `Secure` cookies, sends HSTS and hides `/api/docs`.
2. Serve everything over **HTTPS** from **one origin**: build the frontend (`npm run build`) and serve `frontend/dist` from the same host as `/api` (reverse proxy), so the session cookie stays first-party.
3. Send this Content-Security-Policy with the front-end pages (it is generated by `frontend/vite.config.ts`; run `npm run preview` and read the response header, or print `CSP` from that file). The hash covers the single inline theme script, so regenerate it if that script changes:

   ```
   default-src 'self'; script-src 'self' 'sha256-<hash printed by npm run preview>'; style-src 'self' 'unsafe-inline'; img-src 'self' data:;
   connect-src 'self'; font-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
   ```

   `style-src 'unsafe-inline'` is needed because the charts set inline styles.
4. Enforce a **request body size limit** at the proxy (the app only checks declared `Content-Length`) and timeouts.
5. Use **PostgreSQL**: set `DATABASE_URL` (for example `postgresql+psycopg://user:pass@host/db`), install a driver such as `psycopg`, run `alembic upgrade head`, and **test the migrations on an empty Postgres first**: only SQLite has been exercised. Money is `NUMERIC(12,2)`; SQLite behaviour may differ.
6. Run `uvicorn app.main:app` **without `--reload`, as a single process** (rate limiters and in-process audit/competitor tasks are in memory; a restart marks running work as failed), behind the proxy.
7. Apply **egress filtering** so the server cannot reach internal networks even if the in-app SSRF guard had a bug.
8. Back up the database, keep `.env` out of version control, and re-run `npm audit` and `pip-audit` before each release.
9. Set AI keys only if you want AI features, and read [AI_INTEGRATION.md](AI_INTEGRATION.md): the provider code has never been exercised against a real provider.

## What a production setup would still need

A process supervisor (or container), log shipping, monitoring and alerting, scheduled database backups, a real job queue if audits must survive restarts or run in parallel, and a passed security review appropriate to the data you hold.
